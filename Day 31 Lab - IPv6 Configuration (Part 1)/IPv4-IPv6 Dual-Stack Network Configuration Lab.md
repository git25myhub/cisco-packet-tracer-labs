# IPv4/IPv6 Dual-Stack Network Configuration Lab

## Overview

This lab introduces **IPv6 configuration and dual-stack networking** using Cisco Packet Tracer.

The IPv4 configuration of all devices has already been completed. The objective is to add IPv6 addressing and routing while keeping the existing IPv4 configuration operational. At the end of the lab, the network should support communication using **both IPv4 and IPv6**.

## Lab Objectives

By completing this lab, you will:

- Enable IPv6 unicast routing on a Cisco router.
- Configure IPv6 addresses on router interfaces.
- Verify IPv6 interface configuration.
- Configure IPv6 addresses on PCs.
- Configure IPv6 default gateways.
- Test IPv4 connectivity between PCs.
- Test IPv6 connectivity between PCs.
- Troubleshoot IPv6 connectivity when communication initially fails.
- Demonstrate an IPv4/IPv6 **dual-stack network**.

---

## Network Requirements

The network consists of:

- **R1** — Cisco 2911 router
- Multiple PCs connected to R1 through separate IPv4/IPv6 networks
- Existing IPv4 configuration
- IPv6 addressing using the documentation prefix `2001:DB8::/32`

### IPv4 Addressing

The existing IPv4 configuration uses the following networks:

| Interface | IPv4 Network | R1 IPv4 Address |
|---|---|---|
| G0/0 | `192.168.1.0/24` | `192.168.1.1` |
| G0/1 | `192.168.2.0/24` | `192.168.2.1` |
| G0/2 | `192.168.3.0/24` | `192.168.3.1` |

### IPv6 Addressing

The corresponding IPv6 networks are:

| Interface | IPv6 Network | R1 Global IPv6 Address |
|---|---|---|
| G0/0 | `2001:DB8:0:1::/64` | `2001:DB8:0:1::1/64` |
| G0/1 | `2001:DB8:0:2::/64` | `2001:DB8:0:2::1/64` |
| G0/2 | `2001:DB8:0:3::/64` | `2001:DB8:0:3::1/64` |

> **Note:** `2001:DB8::/32` is reserved for documentation and lab purposes. It is not intended for use as a production/public IPv6 address range.

# Lab Tasks

## Task 1 — Enable IPv6 Routing on R1

IPv6 routing must be enabled globally on R1 before the router can forward IPv6 packets between different IPv6 networks.

Enter global configuration mode and enable IPv6 unicast routing:

```cisco
R1> enable
R1# configure terminal
R1(config)# ipv6 unicast-routing
```

### Verify

Use:

```cisco
R1# show running-config
```

Confirm that the following command appears:

```cisco
ipv6 unicast-routing
```

---

## Task 2 — Configure IPv6 Addresses on R1

Configure the appropriate IPv6 address on each router interface.

### GigabitEthernet0/0

```cisco
R1(config)# interface gigabitEthernet0/0
R1(config-if)# ipv6 address 2001:DB8:0:1::1/64
R1(config-if)# exit
```

### GigabitEthernet0/1

```cisco
R1(config)# interface gigabitEthernet0/1
R1(config-if)# ipv6 address 2001:DB8:0:2::1/64
R1(config-if)# exit
```

### GigabitEthernet0/2

```cisco
R1(config)# interface gigabitEthernet0/2
R1(config-if)# ipv6 address 2001:DB8:0:3::1/64
R1(config-if)# exit
```

Save the configuration:

```cisco
R1# write memory
```

or:

```cisco
R1# copy running-config startup-config
```

---

# Task 3 — Verify the IPv6 Configuration

Use the following command:

```cisco
R1# show ipv6 interface brief
```

The expected result should resemble:

```text
GigabitEthernet0/0    [up/up]
    FE80::201:97FF:FE9A:AC01
    2001:DB8:0:1::1

GigabitEthernet0/1    [up/up]
    FE80::201:97FF:FE9A:AC02
    2001:DB8:0:2::1

GigabitEthernet0/2    [up/up]
    FE80::201:97FF:FE9A:AC03
    2001:DB8:0:3::1
```

### IPv6 Addresses Present on R1

| Interface | Link-Local IPv6 Address | Global IPv6 Address |
|---|---|---|
| G0/0 | `FE80::201:97FF:FE9A:AC01` | `2001:DB8:0:1::1/64` |
| G0/1 | `FE80::201:97FF:FE9A:AC02` | `2001:DB8:0:2::1/64` |
| G0/2 | `FE80::201:97FF:FE9A:AC03` | `2001:DB8:0:3::1/64` |

### Important Observation

Each interface has both:

1. A **link-local address** beginning with `FE80::`
2. A **global unicast address** from the `2001:DB8::/32` documentation range

Link-local addresses are automatically generated by the router when IPv6 is enabled on an interface.

# Task 4 — Configure IPv6 on the PCs

Configure each PC with the IPv6 address belonging to its connected network.

For example, the PC connected to `G0/1` can be configured as:

| Setting | Value |
|---|---|
| IPv6 Address | `2001:DB8:0:2::2` |
| Prefix Length | `/64` |
| IPv6 Default Gateway | `2001:DB8:0:2::1` |

The PC should retain its existing IPv4 configuration.

### Example PC Configuration

Open:

**PC → Desktop → IP Configuration**

Configure:

```text
IPv6 Address:        2001:DB8:0:2::2
Prefix Length:       64
IPv6 Gateway:        2001:DB8:0:2::1
```

Verify the configuration from the PC command prompt:

```text
C:\> ipconfig
```

Expected information should include:

```text
IPv6 Address....................: 2001:DB8:0:2::2
IPv4 Address....................: 192.168.2.2
Default Gateway.................: 2001:DB8:0:2::1
                                  192.168.2.1
```

---

# Task 5 — Test IPv6 Connectivity

Before testing PC-to-PC communication, verify that each PC can reach its directly connected router interface.

For example:

```text
C:\> ping 2001:DB8:0:2::1
```

A successful result should show:

```text
Reply from 2001:DB8:0:2::1
```

with:

```text
Packets: Sent = 4, Received = 4, Lost = 0 (0% loss)
```

This confirms IPv6 connectivity between the PC and R1.

---

# Task 6 — Test PC-to-PC Connectivity

Once the PCs have IPv6 addresses and correct default gateways, test communication between PCs on different IPv6 networks.

For example:

```text
C:\> ping 2001:DB8:0:2::2
```

A successful result should resemble:

```text
Reply from 2001:DB8:0:2::2: bytes=32 time<1ms TTL=127
Reply from 2001:DB8:0:2::2: bytes=32 time<1ms TTL=127
Reply from 2001:DB8:0:2::2: bytes=32 time<1ms TTL=127
Reply from 2001:DB8:0:2::2: bytes=32 time<1ms TTL=127

Packets: Sent = 4, Received = 4, Lost = 0 (0% loss)
```

Because the destination PC is on a different IPv6 subnet, the packet must be routed through R1.

---

# Task 7 — Test IPv4 Connectivity

The existing IPv4 configuration should continue working after IPv6 is added.

Test the IPv4 address of the remote PC:

```text
C:\> ping 192.168.2.2
```

Confirm that the PC receives replies.

The objective of a dual-stack network is that **both protocols operate independently on the same network infrastructure**.

# Troubleshooting

During testing, an IPv6 ping may initially fail even though the router configuration is correct.

For example:

```text
C:\> ping 2001:DB8:0:2::2

Request timed out.
Request timed out.
Request timed out.
Request timed out.

Packets: Sent = 4, Received = 0, Lost = 4 (100% loss)
```

If this occurs, check the following.

### 1. Verify IPv6 Routing

On R1:

```cisco
R1# show running-config
```

Confirm:

```cisco
ipv6 unicast-routing
```

is present.

### 2. Verify Router IPv6 Addresses

Run:

```cisco
R1# show ipv6 interface brief
```

Confirm that all required interfaces have the correct IPv6 addresses and are `up/up`.

### 3. Verify the PC IPv6 Address

On the PC:

```text
C:\> ipconfig
```

Confirm that the address belongs to the correct `/64` network.

For example:

```text
IPv6 Address: 2001:DB8:0:2::2
```

must use the `2001:DB8:0:2::/64` network.

### 4. Verify the IPv6 Default Gateway

The PC connected to `2001:DB8:0:2::/64` should use:

```text
2001:DB8:0:2::1
```

as its IPv6 default gateway.

### 5. Test the Local Router First

Before testing another PC, ping the local router interface:

```text
C:\> ping 2001:DB8:0:2::1
```

If this fails, troubleshoot the PC-to-router connection before testing remote networks.

### 6. Use Traceroute

If the destination is reachable but the ping behaves unexpectedly, use:

```text
C:\> tracert 2001:DB8:0:2::2
```

The first hop should normally be R1's IPv6 interface.

# Lab Results

The router configuration successfully demonstrates IPv4/IPv6 dual-stack operation.

R1 was configured with:

```text
ipv6 unicast-routing
```

and the following global IPv6 addresses:

```text
G0/0 → 2001:DB8:0:1::1/64
G0/1 → 2001:DB8:0:2::1/64
G0/2 → 2001:DB8:0:3::1/64
```

The router automatically generated link-local IPv6 addresses on its interfaces.

Testing also demonstrated that IPv6 packets can be routed between different IPv6 networks once the PCs are correctly configured with their IPv6 addresses and default gateways.

For example, the PC configured as:

```text
IPv6 Address: 2001:DB8:0:2::2
IPv6 Gateway: 2001:DB8:0:2::1
```

was able to successfully reach R1 at:

```text
2001:DB8:0:2::1
```

and eventually successfully communicate with the remote IPv6 destination.

# Conclusion

This lab demonstrates the implementation of an **IPv4/IPv6 dual-stack network**.

IPv4 and IPv6 can operate simultaneously on the same router interfaces and end devices. Enabling IPv6 routing on R1 allows the router to forward IPv6 traffic between the different `/64` networks, while the existing IPv4 configuration continues to provide IPv4 connectivity.

The key concepts demonstrated are:

- IPv6 global unicast addressing
- IPv6 link-local addressing
- IPv6 unicast routing
- IPv6 default gateways
- IPv6 connectivity testing
- IPv4/IPv6 dual-stack operation
- Basic IPv6 troubleshooting
